The Jackil helpdesk
Jackil is a self-hosted IT ticket-management app for a single organization with departments. Django 5.2 + DRF, Postgres in production or SQLite in dev, built as a small core with optional modules that attach through signals. This guide covers setup, day-to-day use, and the API.
Django 5.2 LTS DRF REST API Self-hosted Modular
Introduction
What is Jackil?
A complete helpdesk you run yourself — email-to-ticket, SLAs, automation, a knowledge base, and a REST API — fully under your control.

Jackil turns inbound requests (from the web portal or a monitored email inbox) into tickets that agents triage, discuss, and resolve. It is built for one organization split into departments, with three roles — admin, agent, and customer — and a warm, focused UI.

✦
Conversations, not tickets
Every ticket is a threaded conversation with public replies, internal notes, attachments, and a full system audit trail.
✉
Email in & out
Poll an IMAP inbox to create and thread tickets; replies go back out over SMTP. Customers never need an account.
⚡
SLA & automation
Business-hours SLA targets, breach escalation, and rule-based automation that fires on create, reply, and status change.
◈
Knowledge base
Publish self-service articles so customers can deflect common issues before they open a ticket.
⧉
Custom forms
Define request forms with typed custom fields, so the right details arrive with every new ticket.
⟐
REST API & webhooks
Full token-authenticated API with outbound webhooks on ticket events, throttling, and bounded pagination.
i
Jackil is modular: the core (accounts, tickets, inbox, KB, notifications) is decoupled from optional modules (SLA, automation, API, reporting, custom fields, branding) that attach through signals and a feature registry. Removing a module degrades gracefully — see Architecture.
Getting Started
Quick Start
Run Jackil locally on SQLite in under a minute.
bash
# clone and enter the project
git clone git@github.com:Susquehanna-Syntax/Jackil.git
cd Jackil

# create the virtualenv (Python 3.13)
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# SQLite dev mode — set USE_SQLITE=1 in .env
python manage.py migrate
python manage.py seed_demo --fresh
python manage.py runserver 127.0.0.1:8000

Open http://127.0.0.1:8000 and sign in with a seeded account:

Three roles gate what each user can see and do.

!
Internal notes are never visible to customers — the visibility check runs on every message and on search results. New agents created via createsuperuser are corrected to the admin role automatically.
Core
Tickets & Conversations
The heart of Jackil — a threaded conversation with an audit trail.

A ticket carries a title, description, department, priority, status, assignee(s), and tags. Its timeline mixes three kinds of message:

  • Replies — public, delivered to the customer (and emailed out if the ticket arrived by email).
  • Internal notes — agent-only, for coordination.
  • System events — automatic audit entries (status changed, priority changed, assigned).

Priorities & statuses

Ticket creation, replies, and status changes emit domain signals. Pro modules subscribe to those signals, so SLA timers, automation rules, and webhooks all fire without the core knowing they exist.

Saved Views
Persist a named filter set on the ticket list and recall it in one click.

Agents filter the ticket list by status, priority, assignment, and search text. Any combination can be saved as a named view — a one-click pill above the list. Mark a view shared to make it available to the whole team; keep it private to yourself otherwise. You can delete your own views at any time.

Views store the raw encoded querystring (e.g. status=open&priority=high), so a saved view keeps working even as new filters are added later. The ★ marks a shared view.

Core
Email Inbox
Turn a monitored mailbox into tickets — no customer account required.

Configure one or more inboxes in the settings console with IMAP (inbound) and SMTP (outbound) credentials. The poll_inbox job fetches unread mail, matches it to an existing ticket by subject reference or opens a new one, and attaches any files. Agent replies are emailed back out through the same inbox.

Add an inbox under Settings → Email Inboxes with host, port, and credentials.
Schedule manage.py poll_inbox (e.g. every minute via cron).
Reply from the ticket view — Jackil sends it out and records an outgoing-email event.
Core
Knowledge Base
Self-service articles that deflect tickets before they are opened.

Admins author KB articles in the console; customers browse and search them from the portal under /help/. Good articles cut inbound volume for the most common questions and can be linked directly into replies.

Core
Notifications & CSAT
Keep participants in the loop and measure how you did.

In-app notifications alert agents and customers to new replies on tickets they participate in, with an unread badge in the sidebar. When a ticket is resolved, the customer can leave a CSAT rating (1–5 stars) — surfaced in reporting so you can track satisfaction over time.

Service Levels
SLA & Escalation
Business-hours response and resolution targets with breach escalation.

Define SLA targets per priority against a business schedule (working days and hours). On ticket creation Jackil computes first-response and resolution due-times using only working minutes. The check_sla job flags breaches and drives escalation; the first agent reply marks first-response met.

ConceptMeaning
SLATargetResponse & resolution minutes for a priority.
BusinessScheduleWorking weekdays and hours the clock counts.
Breach flagsresponse_breached / resolution_breached on the ticket.
Workflow
Automation & Macros
Rules that react to ticket events, and canned responses for agents.

Automation rules match conditions (fields on the ticket) against a trigger — on_create, on_reply, or on_status_change — and apply actions such as setting priority, assigning, or tagging. Macros are reusable canned replies an agent inserts into the composer; they can be personal or shared.

rule
WHEN on_create
IF   priority == "critical"
THEN assign_to = "on-call", add_tag = "escalated"
Intake
Custom Fields & Forms
Capture the right details with typed fields on tailored request forms.

Define custom fields (text, choice, and more) and group them into request forms tied to a department. When a customer opens a ticket through a form, the field values are saved alongside it — so “which laptop?” or “which building?” is answered up front. Field keys are auto-generated and de-duplicated from the label.

Insights
Reporting & Export
Volume, resolution, and satisfaction — plus a safe CSV export.

The reporting dashboard summarizes ticket volume, status distribution, and CSAT. Any ticket list can be exported to CSV. Exports are sanitized against formula injection — cells beginning with =, +, -, or @ are neutralized so a spreadsheet can’t execute them.

!
Any new export or search surface must reapply the same guards: CSV formula-injection sanitizing and internal-note exclusion for customer-visible results.
Integrations
REST API & Webhooks
Token-authenticated endpoints for tickets, with outbound webhooks on events.

Create an API key in Settings → API. Authenticate with an Authorization header. Keys are bound to an agent/admin user; customer keys are rejected.

http
Authorization: Api-Key <your-key>
MethodEndpointDescription
GET/api/v1/tickets/List tickets (paginated).
POST/api/v1/tickets/Create a ticket.
GET/api/v1/tickets/{id}/Retrieve one ticket.
PATCH/api/v1/tickets/{id}/Update a ticket.
POST/api/v1/tickets/{id}/messages/Post a reply or note.

Pagination & throttling

List responses are paginated (count + results), default 25 per page. Clients may request up to 100 with ?page_size=; the cap is enforced server-side. Requests are throttled per authenticated user and per anonymous IP to protect the instance.

bash
curl -H "Authorization: Api-Key <key>" \
     "https://help.acme.com/api/v1/tickets/?page_size=50&status=open"

Webhooks

Register a webhook URL in the console to receive a POST when a ticket event fires — ticket.created and ticket.updated. Payloads carry the event name and ticket data, so you can wire Jackil into Slack, PagerDuty, or your own systems.

Appearance
White-label Branding
Make Jackil yours — product name, tagline, and accent color.

Admins set the product name, tagline, and a single pastel accent (lavender, mint, peach, sky, rose, coral, or lemon) from the settings console. Branding is exposed to every template via a context processor, so it applies across the entire UI instantly.

Reference
Modular Architecture
Optional modules attach to a small core without the core depending on them.

Jackil is a small core (accounts, tickets, inbox, knowledge base, notifications) with optional modules that plug in through three seams:

  • Domain signals — the core tickets app emits ticket_created, ticket_replied, and ticket_status_changed. Modules connect receivers in their AppConfig.ready().
  • Feature registry — config.features.feature_enabled(slug) reports which modules are installed; templates read enabled_features to hide anything absent.
  • Guarded routes — root and console URLconfs, plus nav links, are gated by the registry, so a disabled module leaves no broken links.

Remove any optional module from INSTALLED_APPS and the system check, the test suite, and the rendered UI all keep working — that feature simply disappears.
